# Private placement read capabilities

This opt-in Node/native-helper scope implements the owner-approved `private-placement-read-cap-v1` client read bearer. `Ddb.issuePrivateReadCapability(signer, contract, role)` requires independently trusted private routing policy, authenticates the current private assignment before signing, reuses the EndpointDirectory lifetime bound and the existing 600-second default, and signs the raw keccak256 digest through ML-DSA-87. The nested audience binds chain, contract, manager, supported runtime hash, placement version and full group hash. The host independently checks current signing key, lifetime, current placement/member and applied role/tombstone at every use; only cryptographic verification is cached.

The exact preimage is `NEC-DDB-PVT-CAP\x01 || uint256be(chainId) || contract(20) || manager(20) || runtimeHash(32) || uint64be(placementVersion) || groupHash(32) || uint32be(roleUTF8.length) || roleUTF8 || caller(20) || uint64be(issuedAt) || uint64be(expiry) || uint64be(nonce)`. This is a client read purpose only. Role wire spelling is already canonical Go NormalizeRoleName (Unicode simple lowercase and Go whitespace trimming), 1..64 UTF-8 bytes. Quantities are canonical lowercase hex; addresses/hashes/key/signature use fixed lowercase hex. Public CAP1 bytes, vectors and epoch grace remain unchanged.

`tokenSelect` and `tokenCallReadProcedure` accept the new token only when the Ddb instance has `privateRouting`. They use the existing selected-host policy/connect boundary, then send through the actual authenticated inner TLS channel. The public ingress receives only routing metadata; token, table/query, arguments and results stay inside selected-host TLS. No public RPC fallback, hidden resend, token renewal or audience/version rewriting occurs after a move or failed request. The two existing RPC names and positional params are unchanged; unknown discriminators refuse.

A retained token carries all reads allowed by its role during its lifetime. It authorizes no write, preview, payload intake, host signing or signature delegation, and is not a single-query or single-use credential. Role revoke, key rotation, tombstone, expiry, unavailable policy, placement/member changes refuse even on a cached signature. A move requires a new explicit approval/token. No per-token blacklist is added.

`parseDdbPrivateCapabilityToken(rawJSONString)` catches duplicate/unknown/missing keys, malformed UTF-8 scalar values, noncanonical/overflow quantities and exact key/signature sizes. Object input has already lost any original JSON duplicate-key information. The Go RPC decoder performs strict private dispatch before the typed public/private arm; ordinary no-format CAP1 decoding retains compatibility.

Independent Python golden vectors are pinned in Go and SDK tests. Actual Azure, old-node refusal, PostgreSQL/session/publication and tunnel BASIC qualification remain required; source inspection is not test evidence. The channel preserves hybrid key establishment with classical certificate authentication. No new host-challenge purpose or stronger PQ server-authentication claim is made.
