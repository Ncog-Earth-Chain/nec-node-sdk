# Private transaction outcome SDK (PLACE-03 / NEC-97): test cases

Built in run 22 at `ec7740b35483933de25ba16ad74540d68e2098db`. Scope: an addressed authenticated local outcome read and a one-pass collector whose success requires every explicitly required historical host and independently verified canonical finality. The SDK checks identities, the retained transaction's commitments/TXN/member hashes, exact member-v1 results and channel bindings. Applications supply historical-placement and finality trust through mandatory callbacks; no SDK light client, automatic durability policy, private mutation orchestration, portable certificate or deployment is built here.

Status legend: BASIC = written and green in run 22 | DEFERRED = to write and run later | LIVE = needs a testbed run | OWNER = needs an owner act or an environment this host lacks.

## Acceptance clauses

1. Use the existing unchanged READPROC signature and exact `@ddb/private-txn-outcome/v1` selector, four canonical arguments and fresh per-host/per-attempt read envelopes. No new domain or ordinary SQL fallback.
2. Address the requested validator through independently authenticated complete current assignment and endpoint/channel binding. Never select a reachable substitute or use a generic provider. Preserve the actual Node hybrid socket's certificate/hostname/pin/one-use/redirect/bound checks; add only the dedicated outcome method.
3. Bound and own inputs/results, verify all local identities, decode exact canonical member-v1 data without losing uint64, raw cell bytes or SQL NULL, and never label a local observation globally committed.
4. Revalidate the complete locally retained builder record, salted commitments, DB01 ID, ordered member hashes and exact payloads before accepting completion. `expectedBase` in future mutation composition remains independently trusted, not copied from preview.
5. Require a complete independently trusted historical placement and an explicit nonempty unique required-host subset. Every host must return matching local durable evidence. No default policy, quorum inference, duplicate counting or live-endpoint denominator.
6. Require independent canonical completed-chain finality for the exact commit and full retained DB01 unit, including historical group/journal/digest/root identity. Callback results are caller trust, not SDK proof verification. Finality and required storage durability are jointly necessary.
7. Support explicitly unknown commit hash for lost-response recovery by retained TXN identity, without selecting a plurality, resubmitting SQL or changing the original obligation after current assignment moves. Missing, malformed, conflicting or inaccessible evidence remains pending/unavailable; expiry is not noncommit proof.
8. Document activation/transport/trust limits, preserve existing generic transactions and wallet contract boundaries, and provide a complete later-case ledger. No Ready, new consensus format/domain, migration or live deployment.

## Live and owner items

This lane runs only BASIC focused tests and an existing loopback TLS fixture, never a live chain testbed. Node outcome author validation is a dependency, not proof that full private admission is open. Real chain recovery and finality-trust implementation remain in the later integration cases. Browser/mobile require their own actual authenticated PQ transport; the common callback interface does not qualify one. CI/publication, activation and online deployment remain root/owner work.

## Residual risks

Trusted callbacks can falsely assert chain or channel trust. SDK input equality and canonical decoding do not make those assertions cryptographic proofs. Even a correct callback-driven collector does not supply portable evidence for other clients. Completion is relative to the explicit selected required-host set, not an automatically discovered global policy. Retained payloads/salts are sensitive application-owned material; JavaScript copies cannot promise forensic zeroization. Removing a historically required host or pruning authorization/history may leave completion unresolved until an authorized recovery path exists. This slice does not change governance parameters, consensus validity, schemas or migration formats, so flag-off older-binary consensus verdicts are unaffected; the new RPC's prior-node refusal is still listed separately.
