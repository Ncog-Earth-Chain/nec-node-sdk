# Private transaction mutation SDK (PLACE-03 / NEC-97): test cases

Built in run 22 at implementation commit `b469093215e8e71c326fa9e0010f48c46609edf3`. Scope: explicit authenticated prepare, one-host custody and same-unit pending submission; independent accepted BASE/context, local keyed-tag validation, owned retry record, structural root checks and generic-path fences. No application trust adapter, post-root reconstruction, persistent storage, implicit policy, portable proof, browser/mobile transport, consensus change or deployment is built.

Status legend: BASIC = written and green in run 22 | DEFERRED = to write and run later | LIVE = needs a testbed run | OWNER = needs an owner act or an environment this host lacks.

## Acceptance clauses

1. Preparation must return before any payload custody or transaction submission. The caller can persist the retry record, then explicitly store it at selected hosts and submit the same signed unit to an explicit selected recipient.
2. Each input explicitly supplies the existing discovery resolver, trusted assignment/channel policy and recipient validator ID. Common input snapshots own every scalar/array/buffer and capture callback functions before awaits.
3. Retain the exact operation bytes and every intent scalar produced by the local builder before sending. Sign every preparation member hash AS-IS through the existing DdbSigner after route/channel authentication.
4. The SDK compares the independently accepted BASE byte-for-byte against every payload using the existing builder. Neither matching endpoint JSON nor the route alone proves the whole SQL context.
5. Use the caller's local 32-byte digest key with existing buildDdbPrivateTransaction to validate its fingerprint and recompute keyed tags and salted payload commitments. Compare the builder's exact canonical tag arrays against preview stateDelta, preserving sort order and multiplicity.
6. Root checks are deliberately precise: exact 32-byte shape, first prior equal to accepted BASE.initial_anchor, and each later prior equal to the preceding post. Do not claim to compute post roots from prior digests.
7. Each call revalidates the retained record's canonical payloads, salts/commitments, TXN/member hashes, headers, count/order and equality between the unsigned builder envelopes and separately signed envelopes. Preserve exact signatures and stateDelta arrays across copies/retry.
8. Store handles exactly one explicit validator per call. There is no default custody policy and no aggregation that turns one response into group durability.
9. Submit sends the same signed final envelopes with no sidecars or plaintext SQL. After an attempted send, disconnect, malformed reply or node refusal is ambiguous. Never automatically prepare new SQL, regenerate salts or repeat submit.
10. The caller composes the resulting record with collectDdbPrivateTransactionOutcome, supplying its explicit complete historical placement, nonempty required durability set and independent finality policy.
11. Protect generic SDK helpers before signing or private request bytes. PrivateRouting generic calls, numeric op15 units, extracted transaction members and requiresAuthenticatedOutcome completion/retry shortcuts refuse; ordinary public behavior is preserved.
12. Extend the actual Node method allowlist by exactly three methods. Each call gets a fresh authenticated one-use channel, no redirect/reconnect/provider fallback. Document trust/transport/activation limits and keep existing bounds/defaults and domains.

## Residual risks

Caller trust adapters can lie; matching JSON is not chain authentication. Structural root continuity does not derive LtHash lane state. Rehydrated record integrity and cryptographic signer/key authorization are not independently established by local pairing checks. Ciphertext-at-rest custody is the node's responsibility. JavaScript cannot guarantee forensic key erasure. Public unmarked op7/bare-hash/raw Provider traffic cannot be classified reliably. Custody availability and historical evidence retention remain explicit application policy, with no hidden host replacement or quorum claim.
